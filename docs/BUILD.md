# Ssense — Build Guide

> **Note:** An earlier version of this project also compiled a Rust native daemon (`cargo build --release -p ssense-native-daemon`). That component has been removed as of v2.0. There is no Rust compilation step in the current build.

---

## Prerequisites

| Tool | Minimum version | Purpose |
|------|----------------|---------|
| **Node.js** | 20+ | Extension build (Vite + TypeScript) |
| **npm** | 10+ | Package management |
| **Docker + Compose** | 24+ | Server container build |
| **NVIDIA Container Toolkit** | latest | GPU inference (optional for CPU-only test) |
| **Python** | 3.11+ | Server standalone run (without Docker) |

You do **not** need Rust, Cargo, CMake, or any C compiler for the current build.

---

## 1. Extension Build

### Install dependencies

```bash
cd apps/extension
npm install
```

### Configure build credentials

```bash
cp .env.production.example .env.production
```

Edit `.env.production`:

```env
VITE_SSENSE_SERVER_URL=https://api.ssense.app
VITE_SSENSE_API_KEY=<shared-api-key>
VITE_SSENSE_HMAC_SECRET=<shared-hmac-secret>
```

These values are baked into the compiled JS bundle at build time. Every user who installs this build automatically talks to your server with these credentials. See [`docs/SECURITY.md`](SECURITY.md) for the security model behind shared credentials.

For local development (no `.env.production`), Vite falls back to `http://localhost:8080` with empty credentials, which matches the server's dev defaults generated by `apps/slm-server/scripts/run.sh`.

### Build

```bash
npm run build
# Output → apps/extension/dist/
```

The dist directory is a self-contained, loadable Chrome extension. Zero external resources are fetched at runtime.

### Run tests (offline — no network, no npm install needed beyond the above)

```bash
npm test
# Runs 18-case extractor test suite via Node 22's native --experimental-strip-types
# Tests: URL discovery across 6 site archetypes (WordPress, Shopify, OneTrust, etc.)
#        SSRF guard, language-filter correctness, parse latency under 50ms
```

### Load in Chrome

1. Open `chrome://extensions/`
2. Enable **Developer mode**
3. Click **Load unpacked** → select `apps/extension/dist/`

## 2. Server Build

### Option A — Docker (recommended for production)

```bash
cd apps/slm-server

# GPU (CUDA 12, vLLM, full inference)
docker compose up --build -d

# CPU only (testing, no GPU required)
SSENSE_COMPUTE_PROFILE=cpu docker compose up --build -d
```

The `docker-compose.yml` orchestrates two containers:

| Container | Image | Purpose |
|-----------|-------|---------|
| `ssense-slm` | `Dockerfile.gpu` or `Dockerfile.cpu` | FastAPI + vLLM inference |
| `ssense-nginx` | `nginx:alpine` | TLS termination, SSE proxy |

On first boot, `main.py::ensure_models_exist()` downloads model weights from Hugging Face into the mounted `/app/models` volume. This is a one-time operation (~15 GB for the base model + adapters + RAG embeddings).

### Option B — Standalone Python (development / no Docker)

```bash
cd apps/slm-server

python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate

pip install -r requirements.txt
# Key additions over earlier versions: aiosqlite, httpx[http2], beautifulsoup4, lxml

uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```

Verify:

```bash
curl http://localhost:8000/health
# → {"status":"online","backend":"vllm","rag_ready":true,"audit_cache":{...}}
```

### Server environment variables

| Variable | Default | Description |
|----------|---------|-------------|
| `SSENSE_API_KEYS` | — | Comma-separated valid API keys |
| `SSENSE_HMAC_SECRET` | — | HMAC signing secret (must match `VITE_SSENSE_HMAC_SECRET` in extension build) |
| `SSENSE_COMPUTE_PROFILE` | `gpu` | `gpu` / `cpu` / `jetson` |
| `SSENSE_AUDIT_DB_PATH` | `./data/ssense_audit_cache.db` | SQLite audit cache path |
| `SSENSE_MAX_QUEUE_DEPTH` | `5000` | Circuit breaker: max concurrent in-flight requests |
| `SSENSE_REDIS_URL` | — | Optional Redis for distributed chat rate limiting |
| `SSENSE_ALLOWED_ORIGINS` | `*` | CORS allowed origins |
| `MODELS_DIR` | `/app/models` | Model weights and RAG index directory |

See `apps/slm-server/.env.example` for the full reference.

### Run server security tests

```bash
python -m unittest apps/slm-server/tests/test_server_security.py -v
# 8 tests: HMAC verification, Shannon entropy, schema auto-repair,
#          nonce replay, anti-extraction guard, hallucination gate
# → 8 passed in 0.007s
```

## 3. Release Packaging

### Extension (Chrome Web Store upload)

```bash
cd apps/extension/dist
zip -r ssense-v2.3.0-release.zip .
```

Upload `ssense-v2.3.0-release.zip` through the [Chrome Web Store Developer Dashboard](https://chrome.google.com/webstore/devconsole/).

**Before packaging:**
- Verify `.env.production` contains the production server URL, not `localhost`
- Confirm `VITE_SSENSE_API_KEY` and `VITE_SSENSE_HMAC_SECRET` are the live shared credentials
- Check `apps/extension/public/manifest.json` version number is correct
- Do **not** include `.env.production` in the zip; only include `dist/`

### Server

Tag the release and push the Docker image to your registry:

```bash
docker build -f apps/slm-server/Dockerfile.gpu -t ssense-slm:2.3.0 apps/slm-server/
docker push your-registry/ssense-slm:2.3.0
```

## What Was Removed (v1 → v2)

The following items existed in v1 and are no longer present or needed:

| Removed item | Was used for |
|-------------|-------------|
| `cargo build --release -p ssense-native-daemon` | Building the Rust offline inference binary |
| `node scripts/register-nmh.js` | Writing the Native Messaging Host registry entry |
| `apps/native-daemon/` | Rust source for llama-cpp-rs inference, SQLite WAL cache, 4-byte LE IPC framing |
| `apps/extension/src/background/native-messaging.ts` | `chrome.runtime.connectNative()` bridge |
| `apps/extension/src/background/privacy-store.ts` | IndexedDB store for full ~25 KB policy text |
| `PROXY_FETCH` service-worker handler | Browser-side policy HTML fetching |
| `parsePolicyDocument / pickContentElement / stripNonEnglishLines` in `extractor-core.ts` | Browser-side HTML parsing and language filtering |
| Engine-mode selector (Cloud / Offline toggle) in popup | Switching between daemon and cloud |
| Model download progress UI | Tracking 9 GB GGUF download into `%LOCALAPPDATA%\Ssense\models\` |
| `DOWNLOAD_OFFLINE`, `PAUSE_DOWNLOAD`, `SET_OFFLINE_MODE` message handlers | Daemon download lifecycle |
